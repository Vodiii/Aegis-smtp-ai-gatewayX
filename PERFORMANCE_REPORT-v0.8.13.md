# Отчёт v0.8.13 — категории угроз и метрики QA

## Анализ пользовательского прогона v0.8.12

В приложенном логе зафиксировано:

- 59/70 тестов прошли;
- 70/70 писем получили ожидаемый конечный статус доставки;
- suite end-to-end wall time: 40.417 s;
- worker classification span: 37.434 s;
- сумма индивидуальных длительностей: 952.950 s;
- средняя длительность: 13,613.6 ms; p50: 4,253 ms; p95: 35,463 ms; максимум: 35,508 ms.

Это не противоречие: сумма длительностей и среднее по письмам включают перекрывающуюся работу пакетной классификации и повторной проверки. Они не равны общему времени теста. 70/70 в поле доставки означает, что SMTP-маршрутизация сработала, но 11 из 70 категорий не совпали с ожиданием таксономии.

## Почему возникли несовпадения

Основная причина — непоследовательное разрешение пересекающихся категорий между основной пакетной классификацией и вторым проходом AI. Промпт описывал общие границы, но не задавал достаточно точные приоритеты для конкретных конфликтов:

- взрыв/бомба в общественном месте с ультиматумом — `TERRORISM`, а транспортная взрывная угроза без террористического умысла — `TECHNOGENIC`;
- отключение городской энергосети и отравление городского водозабора — `TECHNOGENIC`;
- массовая атака/заложники — `TERRORISM`;
- прямые личные угрозы насилием и вымогательство — `ILLEGAL`;
- взлом с публикацией клиентских данных — `OTHER_THREAT`.

Повторный проход может улучшить результат, но сам по себе не гарантирует совпадения: это ещё один вероятностный ответ модели. Поэтому детерминированные правила таксономии применяются к категории после AI-ответа, а не только в промпте.

## Изменения v0.8.13

- Расширена `app/application/category_policy.py` узкими правилами для перечисленных пересечений категорий.
- Уточнён `UNIFIED_PROMPT`; `BATCH_PROMPT` и `BATCH_REVIEW_PROMPT` строятся на его правилах, поэтому получают одинаковую таксономическую основу.
- Добавлены регрессионные тесты для 11 случаев, которые провалились в последнем логе.
- `BENIGN` намеренно не переклассифицируется этими правилами: категория-policy применяется только к уже обнаруженным угрозам.
- SMTP, batching, API-схема и frontend-контракт не менялись.

## Локальные проверки

- `pytest -q`: **122 passed**.
- P0 failure suite: **4 passed**.
- `compileall`: успешно.
- Симуляция детерминированной политики на 30 угрозах с категориями из предоставленного лога: **30/30 ожидаемых категорий после применения политики**. Это проверка post-processing, а не реальный ответ DeepSeek.

## Что ещё не подтверждено

В этой среде не выполнялся реальный запрос к DeepSeek и не запускался внешний end-to-end QA после исправления. Нельзя утверждать, что внешний набор теперь проходит 70/70, пока пользователь не запустит его с реальным API-ключом.

Запуск в PowerShell:

```powershell
python scripts/run_quality_suite.py --data test-data/external_qa_suite.json
```

Для анализа только классификации без ожидания доставки:

```powershell
python scripts/run_quality_suite.py --data test-data/external_qa_suite.json --classification-only
```

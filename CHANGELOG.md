# История изменений

## v0.8.10 — исправление категории широкомасштабной огненной атаки

- Исправлена узкая политика категорий: угроза широкомасштабной/массовой атаки, первоначально отнесённая к `OTHER_THREAT`, теперь переводится в `TERRORISM`, если текст соответствует существующим сигналам массовой атаки и не похож на личную физическую угрозу.
- Добавлен регрессионный тест для `terrorism_05` — единственного несовпадения категории во внешнем QA v0.8.9.
- Пакетирование, ожидание повторной проверки, API-маршруты и формат ответа frontend не менялись.

## v0.8.9 — пакетная повторная проверка на одном ключе

- Удалена зависимость от второго API-ключа: первичная классификация и повторная проверка используют `DEEPSEEK_API_KEY_PRIMARY`.
- Сомнительные результаты отправляются в потокобезопасную очередь, которая собирает пакет до 10 писем и ожидает не более 0,1 секунды.
- `BENIGN` после первичной AI-классификации повторно оценивается без опоры на локальный score; это сохраняет шанс обнаружить угрозы, для которых локальные сигналы не сработали.
- `OTHER_THREAT` повторно проверяется при локальном риске/сигналах, низкой уверенности или конфликте с сильными сигналами.
- Некорректные/неполные ответы пакета получают отдельную метку и попадают в повторную проверку вместо N одиночных запросов.
- При отказе повторной проверки спорный `BENIGN` превращается в консервативный `OTHER_THREAT` для ручной проверки и уведомления.
- Если первичный API недоступен, сообщение, для которого локальный фильтр требовал ИИ, не должно молча считаться безопасным.
- Добавлены тесты на повторную проверку тем же ключом, склейку заявок из параллельных потоков и безопасный fallback.

Эта сборка локально тестируется; внешний QA из 70 писем и реальная задержка с рабочим DeepSeek API должны быть проверены отдельно.

## v0.8.7 — защитная выборочная перепроверка пакетов

- Добавлена одиночная перепроверка результатов пакетного AI, ошибочно помеченных как `BENIGN`.
- Добавлена выборочная одиночная перепроверка `OTHER_THREAT`, если локальный Risk Engine подтверждает дополнительные признаки риска.
- Если проверка `BENIGN` результата недоступна, создаётся консервативное решение `OTHER_THREAT` с обязательной ручной проверкой и уведомлением.
- Источник пакетной классификации отдельно обозначается `AI_BATCH`; исходный API-контракт по полям ответа не меняется.
- Восстановлена форма JSON-схемы одиночного prompt из v0.8.5.
- Добавлены три регрессионных теста для проверки конфликтующих и отказных сценариев пакетной классификации.
- Существующая пакетная обработка, размер очереди, задержка ожидания и размер AI-пакета не менялись.

Проверки в локальной среде: 88 автоматических тестов PASS, 4/4 P0-теста PASS, локальный Risk Gate Benchmark: 40/40 синтетических угроз отправлены в AI, 0 опасных обходов FAST. Внешний 70-писемный QA v0.8.7 ещё не выполнялся с реальным DeepSeek.

# Changelog

## v0.8.6 — пакетная классификация ИИ

- Добавлена сборка фоновых заданий в пакеты: до 20 писем на одну итерацию очереди.
- Ожидание пополнения пакета ограничено 250 мс после первого задания, чтобы не задерживать малый трафик на несколько секунд.
- Письма, требующие AI, отправляются в DeepSeek пакетами до 10 элементов; письма FAST-пути исключаются из AI-пакета.
- Добавлен отдельный JSON-формат пакетного ответа с ID каждого письма; результаты сопоставляются по ID, а не по порядку ответа.
- При неполном или некорректном элементе повторно запрашивается только соответствующее письмо; при сетевом отказе пакета используется локальный fallback без серии дополнительных сетевых запросов.
- Сильные локальные сигналы по-прежнему запускают индивидуальную перепроверку, если пакетная модель ответила BENIGN.
- Добавлены конфигурация `QUEUE_BATCH_MAX_MESSAGES`, `QUEUE_BATCH_WAIT_SECONDS`, `DEEPSEEK_BATCH_SIZE` и тесты пакетной классификации/очереди.
- Добавлена документация с точными prompts и отдельный отчёт производительности. Реальная задержка DeepSeek в этой среде не измерена.

## v0.8.5 — оптимизация производительности

- Добавлен постоянный HTTP-клиент DeepSeek с повторным использованием соединений.
- Добавлен счётчик HTTP-попыток DeepSeek и замер времени каждой попытки в журнале.
- Ограничен максимальный размер генерируемого JSON-ответа до 256 токенов.
- Предварительно рассчитаны логарифмы вероятностей символьной модели и компактные формы ключевых терминов.
- Сокращено число вызовов символьной модели для обычных, не обфусцированных писем.
- Явные контексты завершённого события, цитаты и метафор могут снять отдельный лексический сигнал при отсутствии других опасных признаков.
- Исправлена ложная маркировка словосочетаний через дефис со смешанными алфавитами как обфускации.
- Классификационная политика и категории угроз не менялись; добавлены регрессионные тесты.


## v0.8.4 — mock emergency-call backend

- Added `GET /api/emergency-services` for a frontend dropdown with four mock-only service entries.
- Added `POST /api/messages/{message_id}/emergency-calls` to record a simulated call request for a message classified as a threat.
- Added `GET /api/messages/{message_id}/emergency-calls` to retrieve the persisted simulation history.
- Added SQLite persistence for call-action audit records.
- Added explicit `MOCK`, `SIMULATED`, and `real_call_placed: false` indicators; all numbers are `TEST-*` placeholders and cannot be dialed.
- Added API validation for missing messages, non-threat messages, and invalid service IDs.
- Added five tests for catalog response, simulated call creation, persistence across repository restart, non-threat rejection, and request validation.


## Примечание к измерениям v0.8.5

- Локальная маршрутизация внешнего набора: 34/70 сообщений в AI вместо 48/70 в v0.8.4; все 30 угроз остаются на AI-пути. Сокращение — 29,17%, поэтому цель −30% на этом наборе почти достигнута, но строго не достигнута.
- Синтетический benchmark (150 benign + 40 угроз): 106/150 benign проходят FAST, 40/40 синтетических угроз направляются в AI.
- Полная задержка с реальным DeepSeek не подтверждена в данной среде; см. `PERFORMANCE_REPORT.md`.

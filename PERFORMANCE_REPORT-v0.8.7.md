# Отчёт по производительности и регрессии — v0.8.7

## Подтверждённые результаты v0.8.6 от пользователя

- Внешний QA: 62/70 PASS (88,57%).
- Обнаружение угроз: 26/30 = 86,67% recall по метке «угроза/не угроза»; четыре угрозы получили `BENIGN`.
- Четыре дополнительных угрозы были обнаружены, но классифицированы не той категорией.
- Ложные срабатывания на 40 benign-тестах: 0.
- Wall time: 64,452 с; throughput по wall time: около 65,2 письма/мин.
- Сумма processing time: 114,340 с; среднее processing time: 1633,4 мс; максимум 5067 мс.

Wall time показывает общий throughput тестового прогона, а processing time — задержку обработки отдельных заданий; это разные показатели. Пакетирование улучшило throughput, но v0.8.6 регрессировала по качеству и не подтвердила цель менее одной секунды задержки на отдельное письмо.

## Изменения v0.8.7

1. Пакетные результаты имеют источник `AI_BATCH`, что позволяет отделить их от одиночных ответов в аудите.
2. Каждый пакетный `BENIGN` результат перепроверяется одиночным вызовом DeepSeek. Это направлено на устранение false negatives, выявленных в v0.8.6.
3. Пакетный `OTHER_THREAT` перепроверяется одиночным вызовом, если Risk Engine уже зарегистрировал локальные признаки риска (score >= 0,15, keywords или phrases).
4. При недоступности одиночной проверки спорный `BENIGN` не оставляется без оповещения: используется `OTHER_THREAT` с `source=FALLBACK`, что включает ручную проверку по текущей policy.
5. Если весь пакетный запрос DeepSeek завершается ошибкой, local fallback не пропускает как `BENIGN` письмо, которое Risk Engine отметил как требующее ИИ; оно направляется в `OTHER_THREAT` для ручной проверки.
5. Установлен регрессионный тест для угрозы, помеченной пакетом как `BENIGN`, для конфликта категории и для отказа индивидуальной проверки.

## Проверки, выполненные локально

- Автоматические тесты: 88 passed.
- P0 failure suite: 4 passed.
- Risk Gate Benchmark: 150 benign, 106 FAST (70,7%), 44 AI; 40/40 синтетических угроз отправлены в AI; 0 угроз обошли AI.

## Что не подтверждено

Реальный DeepSeek API и внешний набор из 70 писем v0.8.7 из этой среды не запускались: API-ключ пользователя недоступен. Поэтому нельзя заявлять, что v0.8.7 уже вернула результат 70/70 или среднюю задержку ниже одной секунды. Эти два результата нужно подтвердить на рабочем `.env`.

## Ожидаемое поведение запросов

Пусть внешняя выборка приводит к четырём пакетным API-запросам и содержит восемь результатов, требующих одиночной проверки. Тогда общее число запросов составит примерно 12. Это только расчётный пример; реальное число зависит от того, как сообщения сгруппировались в очереди, от повторов и формы ответов DeepSeek. Измерять нужно счётчик `DeepSeek HTTP request=` в логах, а не число строк `AI` в отчёте QA.
